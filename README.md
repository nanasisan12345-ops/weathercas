# ウェザキャス / WeatherCas

ウェザーニュースLiVE **非公式ファンサイト**。公式の番組表を観測し、出演予定・検索・統計・公式動画とライブチャットをまとめます。

開発中の確認サイトです。

- 確認用URL: https://nanasisan12345-ops.github.io/weathercas/
- ソース: https://github.com/nanasisan12345-ops/weathercas

依頼者の指定でリポジトリとPagesは公開し、HTMLに `noindex, nofollow, noarchive` を指定しています。検索除外は検索エンジンへの依頼であり、認証・閲覧制限ではありません。URLを共有・発見した第三者も閲覧できます。

## 起動

1. Node.js 24 LTSを用意します。収集コマンドを使う場合はPython 3.12以降も必要です。
2. このフォルダーの `run.bat` をダブルクリックします。初回は固定済みの依存を `npm ci` で取得します。
3. 専用Edgeウィンドウが開きます。停止はコンソールのCtrl+C。自動で開かない場合はコンソールのLocal URLを開いてください。

ブラウザーの自動起動が不要な場合は `run.bat --no-browser`。開発サーバーだけなら `npm run dev`、通常は `http://127.0.0.1:5173/weathercas/` です。既に起動していると番号が変わるので、コンソールのURLを優先してください。

設定・ログ・キャッシュ・専用Edgeプロファイル・一時ファイルはプロジェクト内の `Data/`。専用Edgeの初回ダウンロード先は `Data/downloads/` です。既存のプロファイル設定は上書きしません。通常のブラウザーで開いた場合は、そのブラウザーの保存先・プロファイル設定に従います。サーバー停止・専用ウィンドウ終了後、このフォルダーを削除してアプリを除去できます。

`WeatherCas_Starter_Package/` の原本は保持し、Git対象から除外しています。採用ロゴは元PNGと同一のものを使い、ヘッダー背景をCSSで描画しています。

## 実装した機能

- 公式ローリング番組表の定期収集、JST日付整理、年月別JSON、重複排除、予定変更の履歴、失敗時の既存記録保持。
- 今日の予定、日付選択、月間カレンダー、キャスター・番組・年月・確度・文字列検索、直リンクと戻る/進む。
- 確認済み出演と掲載予定を分けたキャスター別・年別・月別・曜日別・番組別集計。
- 公式掲載動画の通常iframe、公式アーカイブリンク、期限切れ・収集失敗時の代替表示。
- 動画の横にYouTube公式ライブチャット。投稿できない場合の公式チャット別ウィンドウ。スマホではYouTube側で視聴・投稿するリンク。
- キャスターの公式プロフィール写真。公式ページで確認できた16名の画像URLを対応付け、取得できないときは代替表示。写真そのものをGitへ保存していません。
- 氏名の横にX・Instagram・TikTokのSVGアイコン。公式プロフィールに掲載された本人のアカウントだけを新しいタブで開きます。未掲載のSNSは表示しません。
- 上部の「ダーク」「ライト」で表示モードを切り替え。初回はOSの設定に合わせ、選択後は同じブラウザーに保存します。
- 全国の今日の天気予報図と台風の日本広域進路図。公式ページが参照する画像をそのまま表示し、5分ごとに再読み込み。画像内の発表日時と出典を保持し、クリックで公式の詳細を開きます。
- 動画のすぐ下だけに置いた「録画開始」「録画停止」、経過時間・容量・実際の画質、停止後プレビューとMP4保存。
- GitHub Actionsの収集・テスト・データ保存・Pages公開設定、Dependabot、誤り報告用Issuesテンプレート。

依頼者の指定に従い、紹介文・時刻メモ・取得状況とデータの出典欄・4つの概要集計カード・重複する「録画する」リンクと録画メニューは画面から削除しました。メニューはホーム→ライブ視聴→天気・台風→出演番組表→出演履歴→出演統計の順です。出典の記録はこのREADMEとDATA_SOURCES.mdに保持しています。

## 録画の使い方（Windows 64bitのローカル版）

1. `run.bat` で起動し、動画下の「録画開始」を押します。初回はyt-dlpとFFmpegをGitHubから `Data/tools/recording/` へ取得し、固定SHA256で照合します。
2. 「録画中」の表示を確認し、必要な場面の終わりで「録画停止」を押します。
3. プレビューを確認して「MP4をPCに保存」でダウンロードします。元ファイルも `Data/recordings/<ID>/recording.mp4` に残ります。

**配信の映像と音声を直接取得し、再圧縮せずMP4にまとめます。** プレイヤーのタイトル・操作UI、マウスポインター、コメント欄は入りません。配信の映像自体に含まれるテロップは残ります。プレイヤーの表示サイズ・画質選択・ミュート設定による画質・音声への影響はありません。

AVC/H.264とAACの公開HLSを選択し、最大1920×1080・60fpsで保存します。配信が30fpsなら30fpsのままで、フレーム補間・拡大・再エンコードは行いません。実際の取得画質を画面に表示します。録画は配信の最新地点から始まり、巻き戻したプレイヤーの位置とは一致しません。HLSのセグメント単位のため、クリック時刻から数秒のずれが生じます。

公式一覧の現在の動画IDと公式チャンネルIDを照合します。録画許諾取得済みという依頼者の申告に基づく機能です。ログイン・Cookie・DRM解除は使用せず、認証必須・DRM付き配信は対象外です。

1回最大30分・約2GBで自動停止します。停止後に映像・音声・再生時間を検査し、保存可能なデータだけを提示します。通信が途中で切れた場合は、保存できた部分と警告を表示することがあります。ブラウザーを閉じてもNodeサーバー起動中は録画が続くため、終了前に「録画停止」を押してください。過去ファイルは自動削除しません。

**GitHub Pagesではこの録画処理は動きません。** Pages版ではローカル起動が必要という案内と無効な録画ボタンを表示します。Windows 64bit・Node.js 24以降とインターネット接続が必要です。ツールは `config/recording-tools.json` の公式リリースURL・バージョン・ハッシュで固定しています。

## コメント

YouTube公式iframeを使用します。チャットの `embed_domain` は現在のページのホスト名から生成するため、GitHubユーザー名・独自ドメインに追従します。動画と同じIDを使います。

run.bat・npm run dev・静的確認版のNodeサーバーでは、公式動画一覧をサーバーが60秒キャッシュで確認します。画面も60秒ごとに読み直し、配信IDが変わると動画とチャットを一緒に更新します。番組の切り替わり直後は公式側の更新とキャッシュ分だけ遅れる場合があります。取得失敗時は古い動画を現在配信として表示しません。公開済みHTMLだけを別の静的ホストで配信する場合はこのサーバー処理が動かないため、Actionsで生成するlive.jsonの更新に依存します。

投稿・アカウント・配信側の参加条件はYouTubeが管理します。ログインや第三者Cookie制限、登録者限定、チャット無効、配信終了等により埋め込み欄で書き込めない場合は「公式チャットでコメントを書く」で開いてください。本アプリはログイン情報やコメントを受け取らず、代理投稿もしません。モバイルWebでの埋め込み非対応は[公式ヘルプ](https://support.google.com/youtube/answer/2524549?hl=JA)に従います。

## データ取得と限界

取得元・HTTP/robots確認・レート・確度の説明は [DATA_SOURCES.md](DATA_SOURCES.md)。日付のない公式番組表の先頭を現在枠としてJST取得時刻から整理し、日付の巻き戻りで翌日に進めます。曖昧な起点・空応答・構造変化・異常値は採用しません。番組表は**予定**であり、時間が過ぎても実際の出演へ自動昇格しません。

過去全期間の埋め戻し、出演実績の自動確定は未対応です。確認済みの実績がないときは0件を表示します。写真対応表は在籍名簿や全キャスター数を意味しません。

```powershell
python -m collector.collect
python -m collector.collect --validate-only
python -m unittest discover -s tests -v
npm test
npm run build
npm run test:e2e
```

collectorはPython標準ライブラリのみです。WindowsのEdgeでE2Eを実行します。ブラウザー一時ファイルをアプリ内へ寄せる場合は先に次を設定します（run.batは設定済み）。

```powershell
New-Item -ItemType Directory -Force Data/temp | Out-Null
$env:TEMP = "$PWD/Data/temp"
$env:TMP = $env:TEMP
$env:NODE_USE_SYSTEM_CA = '1'
```

`public/data/YYYY/MM.json` が履歴、`index.json` が年月・名前索引、`status.json` がソース別最新成功/直近失敗、`live.json` が動画状態です。ローカルの実行ログは `Data/logs/collector/YYYY-MM/`。日付・名前・変更履歴を消す前にはGit履歴またはコピーを確保してください。

## 任意のYouTube APIキー

キーなしでも公式掲載動画を発見し、oEmbedで公式チャンネル・埋め込み候補を確認します。この場合は「公式掲載の配信（現在LIVEは未確認）」です。

YouTube Data API v3を有効にし、API制限を設定したキーをGitHub Secretsの `YOUTUBE_API_KEY` に設定すると `channels.list` と `videos.list` でチャンネル、公開状態、埋め込み可否、開始/終了情報を追加検証します。検索APIは利用しません。キーはPythonのHTTPヘッダーのみで使い、フロントへ渡しません。現在状態のAPI応答をGitへ丸ごと保存しません。

通常1回あたり2 APIリクエスト、10分間隔で1日144回なら約288 unitが目安です。再試行で増える場合があるため実際のCloud Consoleの割当を確認してください。APIキー付きの実通信は未検証です。LIVE確認表示は15分、動画候補・収集データの鮮度は4時間で失効します。

## GitHub Pages設定

リポジトリは `nanasisan12345-ops/weathercas`、既定ブランチは `main`、Pages Sourceは **GitHub Actions** です。リポジトリ変数 `SITE_URL` を `https://nanasisan12345-ops.github.io/weathercas/` に設定し、OGPとcanonical URLへ反映します。任意のAPIキーはSecretsの `YOUTUBE_API_KEY` だけに設定してください。

個人アカウントの現行プランで非公開リポジトリからPagesを有効にできなかったため、依頼者が「リポジトリも公開にして、Pagesは検索除外する」を選択しました。HTMLのrobotsメタタグを指定し、検索エンジンに登録しないよう依頼します。アクセス制限や検索除外の完全な保証はありません。

ハッシュ型URLなのでPagesの404リライトは不要です。リポジトリ名を変更する場合は `vite.config.ts` の `base` とテストのbaseURLも変更してください。

定期実行は毎時3/13/23/33/43/53分。動画情報は各回、番組表は前回から3時間以上の経過時に更新します。手動・push時は全体を収集します。実行遅延・スキップ・公開リポジトリ無活動による停止があり、リアルタイム更新を保証しません。再実行はActions → Run workflow。収集失敗でも前回の予定と失敗ステータスを検証して公開し、Actions Summaryに警告を残します。ビルド・テストに失敗した場合は公開しません。10分間隔の実行では1日最大144回の検証・公開があるため、GitHubの実行時間と無料枠を確認してください。

収集・ビルドは読み取り権限、データ保存ジョブだけ `contents: write`、公開ジョブだけ `pages: write` と `id-token: write` に分離しています。pushはビルド元commitからの通常pushのみで、新しいcommitが先にあれば失敗して上書きを防ぎます。ブランチ保護でbotの更新が禁止される場合は保護設定に合わせた運用が必要です。

障害はActions Summary、public/data/status.json、7日保存の検証artifactで確認します。Actions自体の失敗通知はGitHubの通知設定に従います。メールやSlackへの独自送信は行いません。公開リポジトリの無料枠を想定していますが、実行回数・プラン・保存容量によって制限が変わるためGitHub側の利用状況を確認してください。古いartifactを長期間保存しない設定です。

`npm run build:release` は古い出力を使い回さず、`release/weathercas-<日時>-<一意ID>/` に新規作成します。静的サイト・Node標準機能の確認/録画サーバー・ツールの固定設定・run.bat・READMEをまとめます。ソースのData・ブラウザー状態・検証動画・node_modulesは混ぜません。exeと_internalは静的Webサイトのため対象外です。詳細な確認記録は `IMPLEMENTATION.md`。

## 出典・プライバシー

写真・SNSリンクの出典は[公式キャスタープロフィール](https://weathernews.jp/wnl/caster/index.html)。対応表は2026-10-20に確認しました。写真表示時は公式画像配信サーバーへ接続します。動画・チャットはページ表示時にYouTubeへ接続します。第三者側でCookie・広告・アクセスログ等が扱われる場合があります。独自の解析やCookie保存は実装していません。表示モードだけをlocalStorageに保存します。run.batの専用Edgeではプロジェクト内のData/browserに保持します。
